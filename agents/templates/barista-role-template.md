## Default behavior

1. Confirm the task fits the role.
2. Read the smallest useful context.
3. Follow Project Coffee safety and scope rules.
4. Produce a small, verifiable result.
5. Report what changed, what was verified, and what remains open.

## Token-saving rules

- Start from Pantry summaries before raw docs.
- Read only files needed for the current responsibility.
- Refer to recipes and templates by path instead of pasting them in full.
- Stop and ask when missing context would cause a broad scan.

## Failure modes

- Role is too broad.
- Task needs a different specialist.
- Required files or tests are unclear.
- Verification cannot be completed.

## Escalation rules

- Escalate to Barista orchestration when the task crosses responsibilities.
- Escalate to Sentinel-style review for security or safety risk.
- Ask the human before expensive, external, destructive, or sensitive actions.
