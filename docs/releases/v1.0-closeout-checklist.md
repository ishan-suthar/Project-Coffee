# Project Coffee v1.0 Closeout Checklist

Status: Brew 25A draft
Date: 2026-07-08

This checklist validates the Project Coffee v1.0 stronger-base phase before UI
work begins. It is a release readiness framework, not a release tag.

## What v1.0 Stronger Base Means

Project Coffee v1.0 stronger base means the local workflow foundation is ready
for daily use and future UI planning:

- safety rules, approval gates, and Spill Guard habits are documented;
- onboarding can be repeated with templates, installer, Doctor, and Fleet tools;
- local evidence can be found through Pantry Search and Evidence Bundles;
- Roastery, Ledger, House Blend, and routing policy keep model use evidence-based;
- release readiness can be checked locally before tags or handoff;
- humans still review diffs, run tools, approve risky actions, and commit.

This phase intentionally stops before building a chat UI or autonomous agent.

## Readiness Statuses

Use one of these statuses for each closeout area:

- READY: complete, validated, and no known release blocker.
- READY WITH WARNINGS: usable, but has documented limitations that do not block
  the stronger-base tag.
- NOT READY: missing, unvalidated, unsafe, or blocked.

## Must Fix Before Tag

- Unreviewed or unexpected diffs.
- Failing release-check blockers that are not explicitly accepted by the human.
- Generated local artifacts staged for commit, especially raw Roastery outputs,
  local reports, scratch directories, caches, or virtual environments.
- Missing Brew Log closeout for Brew 25.
- Any committed secret, credential, token, private key, or private regulated data.
- Any documentation that implies automatic commits, automatic tagging, or
  automatic remote context sending.

## Acceptable Warnings

These may be acceptable for the stronger-base tag if they are visible in the
closeout evidence:

- A missing real fleet registry when only the example registry is expected.
- Historical warnings already documented in Roastery or Doctor evidence.
- Unknown token or cost values where providers or tools did not expose data.
- Provisional House Blend confidence that remains task-limited.
- Future polish opportunities that do not weaken safety, validation, or handoff.

## Manual Tag Policy

Do not create a release tag automatically. A release tag may be created only
after:

1. Brew 25 closeout evidence is recorded.
2. The human reviews the final diff.
3. The human approves staging and commit.
4. The staged secret-pattern check from Project Coffee policy passes.
5. The human explicitly approves tag creation.

Suggested tag names, only after approval:

- `v1.0`
- `v1.0-stronger-base`

## Future UI Prerequisites

The future Coffee Counter UI should not start until these are present:

- Local Evidence Bundle MVP for grounded local context.
- Model Routing Policy for Decaf/local/remote routing decisions.
- Fleet registry/status layer for multi-project awareness.
- Approval gates for remote context, model cost, House Blend changes, staging,
  commits, and tags.

## Non-goals For v1.0 Stronger Base

- No UI yet.
- No automatic remote context sending.
- No embeddings or vector database unless a future Brew justifies them.
- No auto-commit.
- No background autonomous agent.
- No release tag in this checklist shot.
